Ubuntu 24.04 · first-time setup

Each device first needs its own privately provisioned WireGuard configuration and unique tunnel address. This public page never distributes private keys. Trust the gateway CA before downloading; review scripts before running with sudo.

Already provisioned?
sudo kurukshetra-tor connect
sudo kurukshetra-tor status
curl --max-time 35 https://check.torproject.org/api/ip

After manually verifying Tor and a fresh recovery SSH connection, confirm separately with sudo kurukshetra-tor confirm.
Connect starts a 15-minute rollback trial. Confirm applies only to this session. Disconnect, trial expiry, and reboot restore ordinary networking. Windows has a separate prototype workflow below; it has not been tested on your VM.
Windows 11 · prototype, live testing pending
Install the official WireGuard for Windows application first. Provision a separate private Windows peer profile, with a unique address, gateway DNS, and full-tunnel IPv4/IPv6 routes. Never reuse an Ubuntu private key. The profile is not downloadable from this public page.
Use Administrator PowerShell from the Fusion console, not a remote session. Full-tunnel guarding may block local-network access. Trust the gateway CA, review the downloaded script, and follow your PowerShell execution policy.
.\windows-tor.ps1 -Action Connect
.\windows-tor.ps1 -Action Status
.\windows-tor.ps1 -Action Check

When finished, restore ordinary networking separately with .\windows-tor.ps1 -Action Disconnect.
The Windows script installs private settings without connecting. Connect creates a manually started tunnel service; there is no Ubuntu-style rollback timer. Disconnect removes that service and restores ordinary networking. Reboot does not preserve this manual Tor session. Gateway-loss and IPv6/DNS leak tests on Windows remain pending.
How to read this page
Healthy means a container health check passed. Running means the container is running but has no health check. Not deployed can be normal for optional services. These states do not verify every end-to-end feature.
The collector updates once a minute. This page checks for a new snapshot every 30 seconds while visible. A snapshot older than three minutes is marked stale; previous values are not proof of current availability.
